\begin{abstract}
This proposal presents a hybrid pipeline for LiDAR point cloud processing that combines classical geometric methods with lightweight deep learning models. The pipeline addresses two problems: (1)~segmenting individual objects from raw LiDAR scans using geometry-based clustering and a learned classifier, and (2)~reconstructing dense object shapes from sparse partial observations using a Point Completion Network. Unlike end-to-end deep learning approaches that require large annotated datasets and offer limited interpretability, the proposed modular design allows each stage to be inspected, evaluated, and improved independently. The work targets the SemanticKITTI autonomous driving benchmark.

\keywords{LiDAR \and point cloud segmentation \and point cloud completion \and SemanticKITTI \and HDBSCAN \and PointNet \and PCN}
\end{abstract}


\section{Problem Statement}

LiDAR sensors produce point clouds that capture the 3D geometry of driving scenes. Extracting individual objects---vehicles, pedestrians, cyclists---from these scans is essential for autonomous driving perception. Two fundamental problems arise:

\begin{enumerate}
    \item \textbf{Instance segmentation.} Raw LiDAR scans contain tens of thousands of points belonging to the road surface, buildings, vegetation, and objects of interest. The task is to isolate individual object instances from this unstructured data. The challenge is that non-object structures (vegetation fragments, building corners) can be geometrically similar to vehicles, leading to high false-positive rates in purely geometric approaches.

    \item \textbf{Shape completion.} Single-scan LiDAR captures only the side of an object facing the sensor, producing sparse partial observations. For downstream tasks such as tracking, motion planning, or 3D reconstruction, a dense and complete shape representation is needed. The challenge is bridging the domain gap between synthetic training data (clean CAD models) and real LiDAR observations (noisy, sparse, occluded).
\end{enumerate}

End-to-end deep learning methods achieve strong benchmark results on these tasks but require per-point semantic annotations for training, provide limited interpretability when failures occur, and are difficult to diagnose stage by stage. This motivates exploring whether a \emph{modular hybrid approach}---classical geometry for spatial decomposition, lightweight learned models for discrimination and reconstruction---can achieve competitive quality while remaining transparent and easy to debug.


\section{Proposed Approach}

The pipeline processes each LiDAR frame through two phases: object segmentation and shape completion.

\subsection{Phase 1: Object Segmentation}

The segmentation phase decomposes the raw point cloud into individual object instances through a sequence of stages:

\begin{enumerate}
    \item \textbf{Preprocessing.} Height filtering and statistical outlier removal reduce sensor noise. Voxel-grid downsampling controls point density.
    \item \textbf{Ground removal.} RANSAC fits a ground plane, and points below the plane are separated. A normal vector check ensures the fitted plane is approximately horizontal.
    \item \textbf{Clustering.} HDBSCAN groups non-ground points into candidate object clusters. Unlike fixed-radius DBSCAN, HDBSCAN adapts to the density gradient inherent in LiDAR scans (dense nearby, sparse at range).
    \item \textbf{Geometric filtering.} Oriented bounding box properties---volume, height above ground, vertical span, aspect ratio---reject clusters that are geometrically inconsistent with vehicle-sized objects.
    \item \textbf{Learned classification.} A lightweight PointNet-based classifier distinguishes vehicles from remaining non-object clusters. The classifier uses a dual-branch architecture: one branch processes point geometry, another processes metric bounding-box features. A two-stage training strategy addresses data scarcity: Stage~A pre-trains on synthetic ShapeNet partial renders with balanced classes, Stage~B fine-tunes on real LiDAR clusters mined from SemanticKITTI ground-truth labels.
\end{enumerate}

\subsection{Phase 2: Shape Completion}

Classified object clusters are passed to a Point Completion Network (PCN) that reconstructs dense shapes from sparse partial inputs. PCN uses a PointNet encoder and a coarse-to-fine decoder with grid folding. The training loss combines Chamfer Distance (CD) for geometric accuracy with Earth Mover's Distance (EMD) for uniform point distribution, addressing the tendency of CD-only training to produce clustered point patterns. The same two-stage training strategy (synthetic pre-training, real-data fine-tuning) is applied to bridge the domain gap.


\section{Issues and Challenges}

\begin{enumerate}
    \item \textbf{Geometric ambiguity.} Vegetation, building fragments, and other non-object structures can have bounding-box dimensions similar to vehicles. Pure geometric filtering cannot fully resolve this---hence the need for a learned classifier---but the classifier itself faces the challenge of generalising across diverse non-object categories with limited training examples.

    \item \textbf{Synthetic-to-real domain gap.} Models trained on clean ShapeNet meshes may fail on real LiDAR data due to differences in point density, noise characteristics, and occlusion patterns. The two-stage training strategy is designed to address this, but the effectiveness of fine-tuning on noisy real clusters (which themselves may be imperfectly segmented) is an open question.

    \item \textbf{Class imbalance.} LiDAR driving scenes are dominated by cars. Rarer classes (buses, motorcycles) have very few training examples in real data, making the classifier prone to bias. The synthetic pre-training stage provides balanced class exposure, but whether this transfers effectively to real-data fine-tuning must be investigated.

    \item \textbf{Distance-dependent degradation.} LiDAR point density drops with distance from the sensor. Objects at 40+ metres may consist of only a few dozen points, making both clustering and classification unreliable. The pipeline must either handle this gracefully or define an effective operating range.

    \item \textbf{Evaluation scope.} The modular pipeline supports only a fixed set of object classes (car, bus, motorcycle). Evaluation must carefully separate the pipeline's ability to detect its supported classes from its correct rejection of unsupported classes (pedestrians, cyclists, trucks), which requires class-aware evaluation protocols.
\end{enumerate}


\section{Expected Contributions}

\begin{enumerate}
    \item A modular, interpretable pipeline for LiDAR object segmentation that combines classical geometry with lightweight learned classification. The modular design allows stage-by-stage failure diagnosis---critical for safety certification---and runs on modest hardware due to the small model footprint (80K-parameter classifier).

    \item Dense shape reconstruction of detected objects from sparse single-scan LiDAR using PCN with a combined CD+EMD loss. Unlike bounding-box-only detection, completed shapes provide object geometry usable for tighter collision avoidance, motion planning, and 3D scene reconstruction.

    \item A two-stage training strategy (synthetic pre-training $\to$ real fine-tuning) for both the classifier and the completion network, dramatically reducing annotation requirements compared to end-to-end methods that need per-point semantic labels.
\end{enumerate}


\section{Evaluation Plan}

Segmentation quality will be measured by precision, recall, F1, and mean IoU against SemanticKITTI ground-truth instance annotations, using IoU-based matching. Completion quality will be measured by Chamfer Distance, Earth Mover's Distance, and F-Score on both synthetic (ShapeNet) and real (KITTI) data. Ablation studies will isolate the contribution of each pipeline stage: geometric filters alone vs.\ with classifier, Stage~A vs.\ Stage~A+B training, CD-only vs.\ CD+EMD completion loss.
